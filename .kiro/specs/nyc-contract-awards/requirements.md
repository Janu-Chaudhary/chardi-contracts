# Requirements Document

## Introduction

This feature adds a new NYC Contract Awards worker to the CHARDI backend. The worker ingests contract award records from the NYC Open Data Socrata dataset `qyyg-4tf5` (Recent Contract Awards), filters to contracts with a start date in 2026, and upserts them into the shared `opportunities` table following the same three-module pattern (`fetcher.py`, `mapper.py`, `main.py`) used by all existing workers.

Two execution modes are required:
- **Initial load**: Downloads the full dataset as a CSV via the Socrata export endpoint, parses it with stdlib only, filters to 2026 start dates, and upserts all matching records.
- **Daily worker**: Queries the Socrata JSON API with `$limit`/`$offset` pagination (1 000 records per page), filters to 2026 start dates, and upserts new or updated records.

Both modes share the same mapper and DB upsert path.

---

## Glossary

- **Worker**: A Python package under `backend/workers/{name}/` consisting of `fetcher.py`, `mapper.py`, and `main.py`, following the pattern established by existing workers (florida, samgov, georgia, etc.).
- **Fetcher**: The module responsible for retrieving raw data from an external source (HTTP requests, CSV parsing, JSON pagination).
- **Mapper**: The module that transforms raw source records into the 23-field tuple required by `OPPORTUNITY_UPSERT_SQL`.
- **Socrata_API**: The NYC Open Data platform API at `data.cityofnewyork.us`, which exposes dataset `qyyg-4tf5` via both a JSON endpoint and a CSV export endpoint.
- **Dataset**: NYC Open Data dataset `qyyg-4tf5` — "Recent Contract Awards", filtered to rows where `type_of_notice_description = "AWARD"`.
- **Daily_Mode**: Execution mode that fetches up to 1 000 records per API call using `$limit` and `$offset` query parameters, intended for scheduled daily runs.
- **Initial_Load_Mode**: Execution mode that downloads the full CSV export of the dataset and processes all rows, intended for one-time backfill.
- **Fingerprint**: A deterministic SHA-256 identifier generated by `backend.core.fingerprint.generate_deterministic_id`, used as the primary key in the `opportunities` table.
- **Upsert**: An `INSERT … ON CONFLICT DO UPDATE` operation executed via `backend.core.db.upsert_opportunities`, which accepts a list of 23-field tuples.
- **Scrape_Run**: An observability record in the `scrape_runs` table, created via `db.insert_scrape_run` and finalized via `db.finalize_scrape_run`.
- **Source_Record_Id**: The `request_id` field from the Socrata dataset, used as the stable identifier for deduplication.

## Requirements

### Requirement 1: Fetcher — Daily JSON API with Pagination

**User Story:** As a CHARDI data pipeline operator, I want the daily worker to fetch NYC contract award records from the Socrata JSON API with pagination, so that all records published on a given day are captured without missing any due to the 1 000-record-per-page limit.

#### Acceptance Criteria

1. WHEN the Daily_Mode fetcher is invoked, THE Fetcher SHALL send HTTP GET requests to `https://data.cityofnewyork.us/resource/qyyg-4tf5.json` using `aiohttp` with the `$limit` and `$offset` query parameters.
2. WHEN a page response contains exactly `$limit` records, THE Fetcher SHALL increment `$offset` by `$limit` and fetch the next page until a page returns fewer records than `$limit`.
3. WHEN all pages have been fetched, THE Fetcher SHALL return the combined list of raw record dicts to the caller.
4. WHEN the Socrata_API returns an HTTP status code in the set {429, 500, 502, 503, 504}, THE Fetcher SHALL retry the request up to 3 times using exponential backoff with jitter before raising an exception.
5. WHEN the Socrata_API returns any other HTTP error status code, THE Fetcher SHALL raise an exception immediately without retrying.
6. THE Fetcher SHALL include a `User-Agent` header on every request using the value from `backend.core.settings.USER_AGENT`.
7. THE Fetcher SHALL apply a per-request timeout of `backend.core.settings.REQUEST_TIMEOUT_SECONDS` seconds.

---

### Requirement 2: Fetcher — Initial Load via Full CSV Export

**User Story:** As a CHARDI data pipeline operator, I want a one-time initial load mode that downloads the complete NYC contract awards CSV and processes all historical records, so that the database is seeded with the full 2026 dataset before daily incremental runs begin.

#### Acceptance Criteria

1. WHEN the Initial_Load_Mode fetcher is invoked, THE Fetcher SHALL send an HTTP GET request to `https://data.cityofnewyork.us/api/views/qyyg-4tf5/rows.csv?accessType=DOWNLOAD` using only Python stdlib modules (`urllib.request`, `csv`, `io`).
2. THE Fetcher SHALL stream the CSV response and parse it using `csv.DictReader` without loading the entire file into memory at once.
3. WHEN the CSV download returns an HTTP error status, THE Fetcher SHALL raise an exception with the HTTP status code included in the error message.
4. THE Fetcher SHALL return the parsed rows as a list of dicts with string keys matching the CSV column headers.
5. THE Fetcher SHALL include a `User-Agent` header on the CSV download request using the value from `backend.core.settings.USER_AGENT`.

---

### Requirement 3: Column Mapping — Source to DB Schema

**User Story:** As a CHARDI data engineer, I want the mapper to extract only the columns that are useful for the database schema, so that the `opportunities` table is populated with clean, well-typed data and irrelevant columns are discarded.

#### Acceptance Criteria

1. THE Mapper SHALL map the following Socrata columns to the 23-field `OPPORTUNITY_UPSERT_SQL` tuple in the order specified by `backend.core.db.OPPORTUNITY_UPSERT_SQL`:

   | Socrata Column | DB Field ($position) | Notes |
   |---|---|---|
   | `request_id` | `source_record_id` ($3) | Stable deduplication key |
   | `short_title` | `title` ($6) | Falls back to `"Unknown Contract"` if absent |
   | `agency_name` | `buyer_name` ($19) | NYC agency issuing the contract |
   | `vendor_name` | `description` ($7) | Used as description proxy |
   | `category_description` | `industry` ($12) | Contract category |
   | `selection_method_description` | `notice_type` ($8) | Award method |
   | `start_date` | `posted_date` ($9) | Parsed to `datetime` |
   | `end_date` | `deadline` ($10) | Parsed to `datetime` |
   | `contract_amount` | `value_numeric` ($14) | Parsed to `float`; `None` if unparseable |
   | `document_links` | `documents` ($22) | Serialized as JSON array |

2. THE Mapper SHALL set the following fixed values for every record:

   | DB Field | Fixed Value |
   |---|---|
   | `source_portal` ($2) | `"data.cityofnewyork.us"` |
   | `portal_region` ($5) | `"City"` |
   | `state_region` ($11) | `"NY"` |
   | `currency` ($17) | `"USD"` |
   | `buyer_type` ($20) | `"City"` |

3. THE Mapper SHALL generate the `id` field ($1) by calling `backend.core.fingerprint.generate_deterministic_id` with `source_portal="data.cityofnewyork.us"` and `source_record_id=request_id`.
4. THE Mapper SHALL set `solicitation_number` ($4) to the value of `request_id`.
5. THE Mapper SHALL set `source_url` ($21) to `f"https://data.cityofnewyork.us/resource/qyyg-4tf5/{request_id}"` when `request_id` is present, and to `"https://data.cityofnewyork.us/resource/qyyg-4tf5.json"` otherwise.
6. THE Mapper SHALL set `raw_payload` ($23) to the full source record serialized as a JSON object.
7. THE Mapper SHALL set `naics_code` ($13), `value_min` ($15), and `value_max` ($16) to `None`.

### Requirement 4: Date Parsing and 2026 Filter

**User Story:** As a CHARDI data pipeline operator, I want only contracts with a start date in calendar year 2026 to be saved to the database, so that the dataset remains focused on current-year awards and does not grow unboundedly with historical data.

#### Acceptance Criteria

1. THE Mapper SHALL parse `start_date` and `end_date` values from ISO 8601 strings (e.g., `"2026-01-15T00:00:00.000"`) and from date-only strings (e.g., `"2026-01-15"`) into Python `datetime` objects.
2. IF a `start_date` value cannot be parsed into a `datetime`, THEN THE Mapper SHALL set `posted_date` to `None`.
3. THE Fetcher SHALL filter the list of raw records and return only those where the `start_date` field, when parsed, falls within the range `2026-01-01` (inclusive) to `2026-12-31` (inclusive).
4. WHEN a record has a `start_date` outside 2026 or an unparseable `start_date`, THE Fetcher SHALL exclude that record from the list returned to the caller.
5. THE Mapper SHALL derive `status` as `"OPEN"` when `end_date` is on or after the current date, and `"CLOSED"` when `end_date` is before the current date or absent.

---

### Requirement 5: Contract Amount Parsing

**User Story:** As a CHARDI data consumer, I want the contract dollar amount stored as a numeric value in the database, so that the frontend can display and sort contracts by value.

#### Acceptance Criteria

1. WHEN `contract_amount` is a non-empty string containing a valid decimal number, THE Mapper SHALL parse it to a Python `float` and store it in `value_numeric`.
2. WHEN `contract_amount` contains currency symbols, commas, or whitespace (e.g., `"$1,250,000.00"`), THE Mapper SHALL strip those characters before parsing.
3. IF `contract_amount` is absent, empty, or cannot be parsed to a float after stripping, THEN THE Mapper SHALL set `value_numeric` to `None`.

---

### Requirement 6: Document Links Serialization

**User Story:** As a CHARDI data consumer, I want document links from the source record stored as a structured JSON array, so that the frontend can render clickable attachment links.

#### Acceptance Criteria

1. WHEN `document_links` is a non-empty string, THE Mapper SHALL serialize it as a JSON array containing a single object with keys `"title"` and `"url"` (e.g., `[{"title": "Document", "url": "<value>"}]`).
2. WHEN `document_links` is absent or empty, THE Mapper SHALL set `documents` to a JSON-serialized empty array (`"[]"`).

---

### Requirement 7: Ingestion Orchestration and Observability

**User Story:** As a CHARDI platform operator, I want the NYC worker's `main.py` to follow the same observability pattern as all other workers, so that scrape runs are tracked in the `scrape_runs` table and errors are logged to `scrape_errors`.

#### Acceptance Criteria

1. WHEN the worker is invoked, THE Worker SHALL call `db.insert_scrape_run` with `source_portal="data.cityofnewyork.us"` before fetching any data, and store the returned `run_id`.
2. WHEN all records have been upserted successfully, THE Worker SHALL call `db.finalize_scrape_run` with `status="SUCCESS"` and the count of upserted records.
3. WHEN an unhandled exception occurs during fetching or upserting, THE Worker SHALL call `db.log_scrape_error` with the `run_id`, `source_portal`, and the exception message, then call `db.finalize_scrape_run` with `status="FAILED"`.
4. THE Worker SHALL accept a `--mode` command-line argument with allowed values `"daily"` (default) and `"initial"`, which selects between Daily_Mode and Initial_Load_Mode fetching.
5. THE Worker SHALL print a summary line to stdout on completion in the format: `Run {run_id} complete: {status} — {records_upserted} records`.
6. THE Worker SHALL be executable as a module via `python -m backend.workers.nyc_contract_awards.main`.
7. WHEN the worker completes, THE Worker SHALL return a dict with keys `run_id`, `status`, `records_upserted`, and `error`.

---

### Requirement 8: No New Dependencies

**User Story:** As a CHARDI maintainer, I want the NYC worker to use only packages already listed in `backend/requirements.txt` and Python stdlib, so that the deployment footprint does not grow and CI does not require additional install steps.

#### Acceptance Criteria

1. THE Worker SHALL use `aiohttp` (already in `requirements.txt`) for all Daily_Mode HTTP requests.
2. THE Worker SHALL use only Python stdlib modules (`urllib.request`, `csv`, `io`, `json`, `datetime`, `re`) for Initial_Load_Mode CSV downloading and parsing.
3. THE Worker SHALL NOT introduce any new entries to `backend/requirements.txt`.
4. THE Worker SHALL use `asyncpg` (already in `requirements.txt`) indirectly via `backend.core.db` for all database operations.

---

### Requirement 9: CI Integration

**User Story:** As a CHARDI platform operator, I want the NYC contract awards worker included in the daily GitHub Actions workflow, so that it runs automatically alongside all other portal workers.

#### Acceptance Criteria

1. THE CI_Workflow SHALL include a `nyc-contract-awards` job in `.github/workflows/daily-ingest-all.yml` that runs `python -m backend.workers.nyc_contract_awards.main --mode daily`.
2. THE CI_Workflow job SHALL use `python-version: '3.12'` and install dependencies from `backend/requirements.txt`.
3. THE CI_Workflow job SHALL NOT require the Playwright Chromium install step, since the NYC worker uses only HTTP APIs.
4. THE CI_Workflow job SHALL set `timeout-minutes: 30`.
5. THE CI_Workflow `verify` job SHALL list `nyc-contract-awards` in its `needs` array so the smoke test runs after the NYC worker completes.
